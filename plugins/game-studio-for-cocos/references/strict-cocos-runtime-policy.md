# Strict Cocos Runtime Policy

This plugin is Cocos-only for playable game, demo, and prototype implementation work.

## Hard Requirements

- Use Cocos Creator 3.x as the runtime and editor target.
- Use TypeScript for gameplay and component code.
- Implement gameplay rendering, scene composition, input plumbing, HUD, menus, physics, animation, and asset loading through Cocos Creator project concepts.
- Keep in-game UI in Cocos UI unless the user explicitly asks for an external Web shell. Even then, DOM is only allowed around a Cocos Web build, not instead of it.
- Treat Cocos Creator Web builds, Preview, or editor-authored scenes as the verification target for screenshots and playtests.

## Disallowed Substitutes

Do not implement playable output with these as the game runtime:

- raw HTML canvas
- vanilla DOM-only games
- custom WebGL renderers
- Phaser
- PixiJS
- Three.js
- React Three Fiber
- Babylon.js
- "Cocos-style" simulations that do not run through Cocos Creator

These tools may be mentioned for comparison, asset preprocessing, repository documentation, or surrounding website chrome, but not as the runtime for game implementation generated by this plugin.

## Required Project Shape

New playable work should produce or target a real Cocos Creator project. Unless the existing project documents a different Cocos-compatible layout, expect this shape:

```text
project.json
assets/
  scenes/
  scripts/
  prefabs/
  resources/        # or documented asset bundles
settings/
```

TypeScript runtime files under `assets/scripts` must import from `cc` and use Cocos component patterns where engine integration is needed:

```ts
import { _decorator, Component, Node } from 'cc';

const { ccclass, property } = _decorator;

@ccclass('GameRoot')
export class GameRoot extends Component {
  @property(Node)
  public player: Node | null = null;
}
```

Plain TypeScript modules may own deterministic simulation state, but Cocos components must be the bridge into scenes, prefabs, cameras, UI, animation, physics, and input.

## Editor Availability Rule

If Cocos Creator is not installed or cannot run in the environment:

- scaffold the Cocos-compatible project structure and TypeScript components
- document the required editor steps for scenes, prefabs, and inspector wiring
- do not replace the game with a raw browser canvas, DOM-only, Phaser, PixiJS, Three.js, React Three Fiber, Babylon.js, or other non-Cocos runtime
- clearly state that editor or Web-build verification is blocked until Cocos Creator 3.x is available

## Screenshot Rule

Screenshots included as proof of playable behavior must come from a Cocos Creator Preview or Web build. If only a mock, static reference, or non-runtime visual is available, label it as such and do not claim it proves the Cocos game runtime.
